# 실제 도서 데이터로 교체하는 방법

지금 들어 있는 `lib/data/books.json`은 기존 32권과 기획용 `books.json`에서 변환한 83권을 합친 **115권 카탈로그**입니다. `lib/data/quizzes.json`에는 시연용 5권의 퀴즈가 있습니다.
제목·작가는 실제 도서지만 **쪽수·난이도·감성 태그는 제가 임의로 넣은 추정치**이므로, 제출 전 검수하거나 교체하세요.

## 1. books.json — 도서 1권의 구조

```json
{
  "id": "bk_033",
  "title": "책 제목",
  "author": "작가",
  "genres": ["소설"],
  "pages": 320,
  "difficulty": 3,
  "mood_tags": ["몰입하고 싶어"],
  "themes": ["키워드1", "키워드2"],
  "series_next": null
}
```

| 필드 | 규칙 | 채우는 법 |
|---|---|---|
| `id` | `bk_숫자3자리`, 중복 금지 | 이어서 번호 부여 |
| `genres` | 아래 8개 중에서만, 1~2개 | 교보문고 분류 참고 |
| `pages` | 정수 | 교보문고/알라딘 상세페이지 '쪽수' 그대로 |
| `difficulty` | 1~5 | 1=만화·짧은 에세이, 2=대중소설, 3=일반 교양, 4=벽돌 교양서, 5=전공·고전 |
| `mood_tags` | 아래 5개 문자열과 **한 글자도 다르면 안 됨** | 책 분위기에 맞는 것 1~2개 |
| `series_next` | 다음 권의 `id` 또는 `null` | 시리즈일 때만 |
| `isbn` | (선택) ISBN13 문자열 | 외부 API 연동 시 매칭 정확도 100% 확보 — API_INTEGRATION.md 참고 |

**허용 장르(8):** `소설` `자기계발` `에세이` `과학` `역사` `경제경영` `인문` `추리·스릴러`
**허용 기분(5):** `위로가 필요해` `자극이 필요해` `몰입하고 싶어` `가볍게 쉬고 싶어` `성장하고 싶어`

> 이 목록을 바꾸고 싶으면 `lib/engine.js` 상단의 `GENRES`/`MOODS`와 `app.js` 상단의 동일 상수를 **함께** 수정해야 합니다.

## 2. quizzes.json — 레이스 가능 책 만들기

퀴즈가 있는 책만 "레이스 가능" 배지가 붙고 레이스를 만들 수 있습니다.

```json
"bk_033": {
  "25":  [ {"id":"f1","q":"질문","options":["보기1","보기2","보기3","보기4"],"answer":0},
           {"id":"f2","q":"...","options":["...","...","...","..."],"answer":2} ],
  "50":  [ ... 2문항 ... ],
  "75":  [ ... 2문항 ... ],
  "100": [ ... 2문항 ... ]
}
```

- 체크포인트 4개(`25/50/75/100`)를 모두 채워야 완주가 가능합니다.
- `answer`는 정답 보기의 **인덱스(0부터)**.
- `id`는 파일 전체에서 중복만 없으면 됩니다.
- 문항 작성 요령: 25%는 초반 설정, 50%는 중반 사건, 75%는 인물·관계, 100%는 결말 직전까지의 내용으로. **읽지 않으면 검색으로도 바로 답하기 어려운 디테일**이 좋은 문항입니다.

## 3. 교체 후 검증 (1분)

```powershell
npm test
```

자동 검증이 전부 ✓면 안전하게 교체된 것입니다. JSON 문법 오류, enum 오타(가장 흔한 실수: `몰입하고싶어`처럼 띄어쓰기 누락)가 있으면 여기서 걸립니다.

### 프로젝트 루트 books.json 다시 반영하기

기획용 `books.json`을 수정했다면 아래 명령으로 앱 카탈로그 형식에 맞춰 다시 병합할 수 있습니다.

```powershell
npm run import:books
npm test
```

기존 도서와 퀴즈 ID는 유지하고, 제목과 저자가 같은 책은 중복 추가하지 않습니다. 장르·기분·난이도는 앱에서 사용하는 값으로 자동 변환됩니다.

## 4. 데이터를 늘릴 때 기준

- 파이프라인이 3중 필터(읽은 책 제외·기분·완독 가능)를 거치므로 **장르당 8권 이상**을 유지해야 극단 입력에서도 추천이 비지 않습니다.
- 레이스 가능 책은 시연 시나리오에 쓸 3~5권만 정성껏 만들어도 충분합니다.

## 5. 알라딘 API로 도서 데이터 가져오기 (연동 준비 완료)

나중에 도서 목록을 API로 채우기로 하셨죠. 코드에는 이미 두 가지가 준비돼 있습니다.

**① 연동 심(seam)** — 도서 데이터 접근이 전부 `lib/catalog.js` 한 파일을 거칩니다. 소스를 바꿀 때 추천 엔진과 API는 수정할 필요가 없습니다.

**② 수집 스크립트** — `scripts/import-aladin.mjs`
알라딘을 기본으로 한 이유: 국내 도서 API 중 **쪽수(itemPage)를 주는 곳이 사실상 알라딘뿐**이고, 쪽수는 완독 기간 계산의 필수 입력입니다. (카카오·네이버 책 검색은 쪽수 미제공)

```powershell
# 1) 알라딘 로그인 → ttb 키 발급: aladin.co.kr/ttb/wblog_manage.aspx
$env:ALADIN_TTB_KEY="발급받은키"

# 2) 검색으로 수집 (또는 --isbn 9791161571188 식으로 정확 지정)
node scripts/import-aladin.mjs --query "미드나잇 라이브러리" --start-id 33 --out import.json
```

출력된 항목은 제목·작가·쪽수·장르(자동 매핑)가 채워진 상태입니다. **difficulty와 mood_tags만 직접 채우고, `_`로 시작하는 검토용 필드를 지운 뒤** `books.json` 배열에 붙여넣으세요.

> 왜 런타임에 API를 직접 부르지 않나요? — 추천 엔진이 쓰는 난이도·감성 태그는 어떤 도서 API에도 없는 **우리 서비스의 큐레이션 자산**이기 때문입니다. "API로 수집 → 사람이 보강 → 카탈로그 반영" 흐름이 품질과 환각 차단(R2 원칙)을 지키는 구조입니다. 발표에서도 이 논리를 그대로 쓰시면 됩니다.

## 6. 제출·배포 전 자동 점검

```powershell
npm run preflight
```

한 번에 검사: JSON 문법 / 장르·기분 enum 오타 / 쪽수·난이도 범위 / 퀴즈 정답 인덱스 / 체크포인트 4종 완비 / **저장소 안 API 키 잔존 여부(sk-, JWT 패턴)** / `.gitignore`의 `.env` 등록.
데이터를 교체했거나 커밋 직전이라면 `npm test`(동작 검증)와 `npm run preflight`(데이터·보안 검증)를 둘 다 돌리세요.
