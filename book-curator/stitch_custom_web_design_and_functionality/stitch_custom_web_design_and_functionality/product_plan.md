# AI 설문 기반 노래 추천 웹 서비스 기획서

## 1. 서비스 개요

사용자가 몇 가지 간단한 설문에 답하면 현재 기분, 상황, 취향을 분석해 어울리는 노래를 추천하는 웹 서비스다. 추천 결과는 OpenAI API의 `gpt-4o-mini` 모델을 사용해 생성한다.

### 핵심 가치

- 검색어를 고민하지 않아도 설문만으로 빠르게 노래를 추천받는다.
- 장르뿐 아니라 감정, 활동, 에너지 수준 등 맥락을 반영한다.
- 추천 이유를 함께 제공해 결과에 대한 공감과 신뢰를 높인다.
- 사용자가 자신의 OpenAI API 키를 입력하는 BYOK(Bring Your Own Key) 방식으로 이용한다.

## 2. 목표 및 범위

### MVP 목표

- API 키 입력 및 유효성 확인
- 5~7개 설문 문항 제공
- 설문 결과를 기반으로 5곡 추천
- 곡명, 아티스트, 추천 이유, 분위기 태그 표시
- 같은 답변으로 다시 추천 및 설문 다시 하기
- 모바일과 데스크톱을 지원하는 반응형 UI

### MVP 제외 범위

- Spotify, Apple Music 등 스트리밍 서비스 계정 연동
- 실제 음원 재생
- 사용자 회원가입 및 추천 이력의 서버 저장
- 협업 필터링 또는 자체 음악 데이터베이스 구축
- 플레이리스트 자동 생성

## 3. 주요 사용자 흐름

1. 사용자가 서비스 소개 화면에 진입한다.
2. OpenAI API 키를 입력하고 이용 안내 및 보안 주의사항을 확인한다.
3. `설문 시작` 버튼을 누른다.
4. 사용자가 문항별 답변을 선택한다.
5. 답변 요약을 확인하고 `노래 추천받기`를 누른다.
6. 서비스가 OpenAI API에 추천을 요청한다.
7. 추천된 5곡과 각 추천 이유를 카드 형태로 보여준다.
8. 사용자는 `다시 추천` 또는 `설문 다시 하기`를 선택한다.

## 4. 화면 구성

### 4.1 시작/API 키 입력 화면

- 서비스명과 한 줄 소개
- OpenAI API 키 입력 필드
  - 비밀번호 형식으로 마스킹
  - 표시/숨김 토글
  - 입력값 앞뒤 공백 자동 제거
- API 키 처리 안내
  - 키는 추천 요청에만 사용
  - 기본값으로 브라우저 영구 저장 금지
  - 화면 새로고침 또는 탭 종료 시 제거
- `설문 시작` 버튼
- OpenAI API 사용량에 따라 사용자 계정에 비용이 청구될 수 있다는 안내

### 4.2 설문 화면

- 현재 문항 번호와 전체 진행률
- 질문과 선택지
- `이전`, `다음` 버튼
- 모든 필수 문항에 답한 뒤 결과 요청 가능
- 한 화면에 한 문항을 표시해 집중도를 높임

### 4.3 로딩 화면

- 추천 생성 중임을 나타내는 애니메이션
- 예시 문구: `당신의 오늘에 어울리는 노래를 찾고 있어요.`
- 중복 요청 방지를 위해 요청 중 버튼 비활성화

### 4.4 추천 결과 화면

- 설문 답변을 한 문장으로 요약한 추천 테마
- 추천 곡 5개
  - 순위
  - 곡명
  - 아티스트명
  - 추천 이유
  - 분위기/장르 태그 2~4개
- `같은 답변으로 다시 추천` 버튼
- `설문 다시 하기` 버튼
- 곡명과 아티스트를 복사할 수 있는 기능

### 4.5 오류 화면/메시지

- API 키 누락: `OpenAI API 키를 입력해 주세요.`
- 인증 실패: `API 키가 유효하지 않습니다. 키를 다시 확인해 주세요.`
- 사용량 또는 결제 문제: `API 사용 한도 또는 결제 설정을 확인해 주세요.`
- 요청 과다: 잠시 후 재시도 안내
- 네트워크 오류: 연결 상태 확인 및 재시도 버튼 제공
- 응답 형식 오류: 자동으로 1회 재시도한 뒤 오류 안내

## 5. 설문 문항 예시

| 번호 | 질문 | 선택지 예시 | 필수 여부 |
|---|---|---|---|
| 1 | 지금 기분은 어떤가요? | 행복함, 차분함, 우울함, 설렘, 답답함 | 필수 |
| 2 | 지금 무엇을 하고 있나요? | 휴식, 출퇴근, 공부/업무, 운동, 드라이브 | 필수 |
| 3 | 원하는 에너지 수준은 어느 정도인가요? | 낮음, 보통, 높음 | 필수 |
| 4 | 선호하는 장르는 무엇인가요? | 팝, K-POP, 록, 힙합/R&B, 인디, 재즈/클래식, 상관없음 | 필수 |
| 5 | 선호하는 보컬은 무엇인가요? | 여성 보컬, 남성 보컬, 혼성/그룹, 연주곡, 상관없음 | 선택 |
| 6 | 익숙함과 새로움 중 무엇을 원하나요? | 유명한 곡, 적절히 섞기, 숨은 명곡 | 필수 |
| 7 | 피하고 싶은 장르나 분위기가 있나요? | 자유 입력(최대 100자) | 선택 |

## 6. 추천 결과 데이터 형식

OpenAI API에는 구조화된 JSON 응답을 요청한다. 화면에서는 JSON을 직접 노출하지 않고 카드 UI로 변환한다.

```json
{
  "theme": "차분한 퇴근길에 어울리는 따뜻한 인디 팝",
  "recommendations": [
    {
      "rank": 1,
      "title": "곡명",
      "artist": "아티스트명",
      "reason": "사용자의 설문 답변과 연결된 간결한 추천 이유",
      "tags": ["차분함", "인디 팝", "퇴근길"]
    }
  ]
}
```

### 응답 검증 규칙

- 추천 곡은 정확히 5개여야 한다.
- 동일한 곡을 중복 추천하지 않는다.
- `title`, `artist`, `reason`, `tags`가 모두 존재해야 한다.
- 추천 이유는 곡마다 1~2문장으로 제한한다.
- JSON 파싱 또는 검증 실패 시 한 번만 자동 재요청한다.

## 7. OpenAI API 연동 기획

### 기본 설정

- 제공사: OpenAI
- 모델: `gpt-4o-mini`
- API 키: 웹페이지에서 사용자가 직접 입력
- 추천 결과: 구조화된 JSON 형식
- 응답 창의성: 동일 답변에서도 어느 정도 다양한 곡이 나오도록 설정

### 요청에 포함할 내용

- 시스템 지침
  - 음악 큐레이터 역할 부여
  - 실제로 존재하는 곡만 추천하도록 지시
  - 설문 답변을 우선 반영하도록 지시
  - 정확히 5곡 및 지정된 JSON 구조로 응답하도록 지시
- 사용자 입력
  - 각 설문 문항과 선택한 답변
  - 사용자가 입력한 제외 조건
  - 이전 추천 결과(다시 추천할 때 중복 방지용)

### 프롬프트 개요

```text
당신은 다양한 국가와 장르의 음악을 아는 큐레이터입니다.
사용자의 설문 답변을 바탕으로 실제 존재하는 노래 5곡을 추천하세요.
각 곡에는 아티스트, 추천 이유, 분위기 태그를 포함하세요.
같은 곡을 중복 추천하지 말고 지정된 JSON 형식만 반환하세요.
```

## 8. API 키 처리 및 보안 정책

브라우저에서 OpenAI API를 직접 호출하면 사용자의 API 키가 해당 브라우저 환경에서 사용된다. 따라서 MVP는 개인용 또는 신뢰할 수 있는 환경에서 사용하는 BYOK 방식으로 한정한다.

- API 키를 서버 데이터베이스, 분석 도구, 오류 로그에 기록하지 않는다.
- API 키를 URL, 쿼리 문자열 또는 화면 상태 공유 링크에 포함하지 않는다.
- 기본적으로 메모리에만 보관하며 `localStorage`에는 저장하지 않는다.
- 새로고침 시에도 유지할 필요가 있다면 `sessionStorage` 사용 여부를 사용자가 명시적으로 선택하게 한다.
- 탭 종료 또는 사용자가 `키 지우기`를 누르면 저장된 키를 제거한다.
- 브라우저 개발자 도구나 악성 확장 프로그램으로부터 키를 완전히 보호할 수 없음을 안내한다.
- 운영/공개 서비스로 확장할 경우 서버리스 함수 또는 백엔드 프록시를 두고, 서비스 소유 API 키를 서버의 환경 변수로 관리하는 구조를 우선 검토한다.
- 사용자 입력과 모델 응답에 API 키가 섞이지 않도록 별도의 상태로 관리한다.

## 9. 추천 품질 및 한계

- 언어 모델이 존재하지 않거나 제목/아티스트가 잘못된 곡을 제안할 가능성이 있다.
- MVP에서는 결과 화면에 `AI 추천 결과이므로 곡 정보를 확인해 주세요.`라는 안내를 표시한다.
- 추후 Spotify, MusicBrainz 등 음악 데이터 API를 연동해 곡 존재 여부를 검증할 수 있다.
- `다시 추천` 요청에는 직전 결과를 제외 목록으로 전달해 다양성을 높인다.
- 특정 답변 하나가 전체 추천을 과도하게 지배하지 않도록 기분, 상황, 장르, 에너지 수준을 균형 있게 반영한다.

## 10. UI/UX 방향

- 감성적이지만 정보가 잘 읽히는 미니멀 디자인
- 설문 답변에 따라 배경 색상 또는 그라데이션을 부드럽게 변화
- 모바일 우선 설계
- 결과 카드에는 음악 앨범 이미지를 임의 생성하거나 잘못 연결하지 않음
- 키보드 탐색, 명확한 포커스 표시, 충분한 명암 대비 지원
- 모든 버튼과 입력 필드에 접근 가능한 라벨 제공

## 11. 권장 기술 구성

- 프론트엔드: React + TypeScript
- 빌드 도구: Vite
- 스타일링: Tailwind CSS 또는 CSS Modules
- 상태 관리: React 기본 상태 관리로 시작
- 입력 검증: Zod 등 스키마 검증 도구
- OpenAI 연동: OpenAI 공식 JavaScript SDK 또는 HTTPS API
- 배포 후보: Vercel, Netlify, Cloudflare Pages

브라우저에서 공식 SDK를 직접 사용할 경우 브라우저 실행을 명시적으로 허용하는 설정이 필요하며, 이는 API 키 노출 위험을 없애주지 않는다. 공개 운영 단계에서는 백엔드 프록시 구조를 권장한다.

## 12. 상태 및 예외 처리

| 상태 | 화면 동작 |
|---|---|
| API 키 미입력 | 설문 시작 또는 추천 요청 차단 |
| 설문 미완료 | 미응답 문항 표시 및 결과 요청 차단 |
| 요청 중 | 버튼 비활성화 및 로딩 표시 |
| 요청 성공 | JSON 검증 후 결과 카드 표시 |
| 인증 실패 | API 키 입력 화면으로 이동하고 수정 안내 |
| 응답 형식 오류 | 자동 1회 재요청 후 실패 메시지 표시 |
| 네트워크 오류 | 현재 설문 답변을 유지하고 재시도 제공 |

## 13. 개인정보 및 데이터 정책

- 회원가입 없이 사용할 수 있도록 설계한다.
- 민감한 개인정보를 설문에서 수집하지 않는다.
- 자유 입력란에 개인정보를 입력하지 말라는 안내를 제공한다.
- 분석 도구를 추가할 경우 설문 원문, API 키, 모델 응답 전체를 수집하지 않는다.
- 추천 이력 저장 기능을 추가할 경우 사용자 동의와 삭제 기능을 제공한다.

## 14. 성공 지표

- 설문 시작 대비 추천 결과 도달률
- 추천 결과 생성 성공률
- `다시 추천` 사용률
- 추천 곡 복사 또는 외부 검색 행동률
- API 오류 유형별 발생률
- 간단한 만족도 평가: `마음에 들어요` / `아쉬워요`

## 15. 개발 우선순위

### 1단계: 기본 MVP

- API 키 입력 UI 및 메모리 보관
- 설문 진행 UI
- `gpt-4o-mini` 추천 요청
- JSON 응답 검증
- 결과 카드와 오류 처리

### 2단계: 품질 개선

- 직전 추천과 중복 방지
- 만족도 피드백
- 추천 결과 공유용 텍스트 생성
- 접근성 및 반응형 UI 개선

### 3단계: 서비스 확장

- 음악 데이터 API를 통한 곡 검증 및 링크 제공
- 스트리밍 플랫폼 플레이리스트 생성
- 사용자 계정과 추천 이력
- 운영용 백엔드 프록시 및 사용량 제한

## 16. 완료 조건

- 사용자가 웹페이지에서 OpenAI API 키를 입력할 수 있다.
- 모든 추천 요청이 `gpt-4o-mini` 모델을 사용한다.
- 설문 완료 후 5곡의 구조화된 추천 결과가 표시된다.
- 추천 이유가 사용자의 설문 답변과 연결되어 있다.
- API 키가 영구 저장되거나 로그에 기록되지 않는다.
- 인증, 네트워크, 한도 초과, 잘못된 응답 오류가 사용자 친화적으로 표시된다.
- 모바일과 데스크톱에서 핵심 흐름을 완료할 수 있다.
